# Data contract

This is the written agreement on what our data looks like. Changing anything here must be announced to the whole team first (rule 5).

## General rules

- **Format:** every Kafka message is one JSON object, UTF-8.
- **Time:** always ISO 8601 in **UTC** with a `Z` at the end, e.g. `2026-11-20T19:00:00Z`. The app converts to local time only for display.
- **Identity:** a pharmacy is identified by its `pharmacy_id` (the `id` in the `pharmacies` table).
- **Kafka key:** use `pharmacy_id` as the key, so messages about one pharmacy stay in order.
- **Bad messages:** a consumer never crashes on a bad message. It logs it and skips it.

## Topic `duty-rota` (owner: Slice A)

"This pharmacy is on duty between these two times."

```json
{
  "pharmacy_id": 1,
  "starts_at": "2026-11-20T19:00:00Z",
  "ends_at": "2026-11-21T07:00:00Z",
  "source": "simulator"
}
```

| Field | Type | Rule |
|---|---|---|
| `pharmacy_id` | integer | must exist in `pharmacies` |
| `starts_at` | UTC timestamp | required |
| `ends_at` | UTC timestamp | required, must be after `starts_at` |
| `source` | text | `simulator`, `manual` or `scraper` |

Consumer rule: insert into `duty_rota`; if `(pharmacy_id, starts_at)` already exists, update `ends_at`. Sending the same message twice is harmless.

## Topic `confirmations` (owner: Slice B)

"A user says this pharmacy is open / closed."

```json
{
  "event_id": "3f2b8c1e-6d1a-4c53-9a39-0b7e4a5d9f10",
  "pharmacy_id": 4,
  "status": "closed",
  "confirmed_at": "2026-11-20T22:15:00Z"
}
```

| Field | Type | Rule |
|---|---|---|
| `event_id` | UUID | generated by the sender, unique per message |
| `pharmacy_id` | integer | must exist in `pharmacies` |
| `status` | text | `open` or `closed` |
| `confirmed_at` | UTC timestamp | when the user tapped the button |

Consumer rule: insert into `confirmations`; if `event_id` already exists, ignore it.

## Tables

| Table | Filled by | Content |
|---|---|---|
| `pharmacies` | seed file now, OpenStreetMap import later (Slice A) | the pharmacies and their position |
| `duty_rota` | the `duty-rota` consumer | on-duty windows |
| `confirmations` | the `confirmations` consumer | open / closed reports |

## The one definition of "open now"

Everybody uses the view **`v_open_now`**. Nobody rewrites this logic in their own query.

A pharmacy is open now when:
1. it is a 24h pharmacy, **or** the current time is inside one of its duty windows, **and**
2. nobody reported it **closed** in the last **60 minutes** (a newer "open" report cancels an older "closed" one).

The view also gives `last_status` and `last_confirmed_at`, for the "Confirmed 12 min ago" label.

| Feature | How it uses the view |
|---|---|
| Nearest pharmacy (Slice C) | `SELECT ... FROM v_open_now ORDER BY geom <-> <user point> LIMIT 3` |
| Filter "Open now" | no filter: the whole view |
| Filter "24h" | `WHERE is_24h` |
| Coverage map (Slice B) | the pharmacies in the view are the "on-duty" ones |

A "Night" filter is postponed until we agree on what "night" means (a duty window is just a start and an end, it is not tied to night).

## Changing this contract

1. Tell the team before you change a message or a table.
2. Database changes are a **new numbered file** in `sql/` (`05_...sql`), never a silent edit of an old one.
3. Update this file in the same change.
